# نظام الحضور والغياب الذكي — جامعة المعقل الأهلية (البصرة)

تطبيق Flutter للهاتف المحمول لتسجيل الحضور بتقنية **QR**، بثلاث لوحات تحكم:

| الدور | ما يمكنه فعله |
|---|---|
| **المدير** | إدارة الكليات والأقسام والمواد، وإدارة الطلاب (بحث، تعديل، تعيين القسم دفعة واحدة)، وإدارة الدكاترة وإسناد المواد إليهم، وتقارير الحضور والغياب مع التصدير إلى Excel (CSV)، وإعدادات الفصل ونسب الإنذار والحرمان، وتهيئة قاعدة البيانات من الملفات المرفقة |
| **الدكتور** | اختيار مواده، وبدء محاضرة وعرض رمز QR يتجدد كل 15 ثانية لمنع التصوير والمشاركة، ومتابعة الحاضرين لحظياً، والتسجيل اليدوي، وإنهاء المحاضرة، وتقرير كل مادة |
| **الطالب** | مسح رمز QR لتسجيل الحضور، ومتابعة نسبة حضوره في كل مادة مع تنبيهات الإنذار والحرمان، وسجل محاضراته |

**طرق الدخول:**
- **الرقم الجامعي (المعرفي) أو الوظيفي** مع كلمة مرور. في أول مرة يضغط المستخدم "تفعيل حساب جديد" ويختار كلمة مروره.
- **حساب Google**. في أول مرة يُطلب الرقم الجامعي وكلمة المرور مرة واحدة لربط الحساب، أو يضيف المدير البريد في ملف الطالب أو الدكتور.

## البيانات المضمّنة

البيانات مأخوذة من الملفين المرفقين وموجودة في `assets/data/`:
- `students.json`: 538 طالباً (المرحلة الثانية والثالثة، صباحي ومسائي)، من ورقة "كل الطلاب" في Students.xlsx.
- `courses.json`: 136 مادة، من Resources.xlsx.
- `structure.json`: كلية الهندسة وأقسامها الثلاثة: هندسة الذكاء الاصطناعي، وهندسة السيطرة والحاسبات، وهندسة الأمن السيبراني.

> ملف الطلاب لا يحدد قسم كل طالب. لذلك يمكن للمدير من شاشة **الطلاب** تصفية الطلاب ثم الضغط على زر "تعيين القسم للمعروضين". وإلى أن يُعيَّن القسم، يُقبل حضور الطالب في أي محاضرة لمرحلته ودوامه.

**قواعد قبول الحضور:**
- تتطابق المرحلة والدوام والقسم إن كان محدداً.
- الرمز صالح زمنياً.
- المحاضرة ما زالت جارية.
- لا يُسجَّل الطالب في المحاضرة الواحدة أكثر من مرة.

## الحصول على ملف APK (بدون تثبيت أي شيء على جهازك)

يحتوي المشروع على بناء تلقائي عبر **GitHub Actions**:

1. أنشئ حساباً مجانياً على github.com، ثم مستودعاً جديداً **خاصاً (Private)**.
2. ارفع محتويات هذا المجلد إلى المستودع:
   - من صفحة المستودع اضغط **Add file ← Upload files**.
   - اسحب كل الملفات والمجلدات، ومنها مجلد `.github` المخفي.
3. يبدأ البناء تلقائياً. تابعه من تبويب **Actions**، ويستغرق نحو 10 دقائق.
4. بعد انتهاء البناء، افتح قسم **Releases** في صفحة المستودع من الهاتف ونزّل ملف `almaqal-attendance-*.apk` وثبّته. قد تحتاج للسماح بالتثبيت من مصادر غير معروفة.

بدون إعداد Firebase يعمل التطبيق في **الوضع التجريبي**: كل البيانات محفوظة على جهاز واحد، وهو مناسب لاستعراض الواجهات.
- المدير: `admin` / `admin123`
- الدكتور: `D1001` / `123456`
- الطالب: "تفعيل حساب جديد" برقمه المعرفي.

> لاختبار الـ QR في الوضع التجريبي تحتاج جهازين يعرضان البيانات نفسها، وهذا غير ممكن محلياً. لذلك يلزم Firebase للاستخدام الفعلي.

## تفعيل الوضع الحقيقي (Firebase) — مجاني

1. ادخل إلى console.firebase.google.com وأنشئ مشروعاً، مثلاً `almaqal-attendance`.
2. من **Build ← Authentication ← Sign-in method** فعّل طريقتين:
   - **Email/Password**
   - **Google**
3. من **Build ← Firestore Database** أنشئ قاعدة بيانات (Production mode، والموقع الأقرب مثل `europe-west`).
   - من تبويب **Rules** الصق محتوى ملف `firestore.rules` واضغط **Publish**.
4. من **Project settings ← Your apps** أضف تطبيق Android:
   - Package name: `iq.edu.almaqal.almaqal_attendance`
   - SHA-1: `6C:1D:65:0B:4E:54:8E:EA:1C:B9:45:69:85:8A:61:9A:AB:FE:03:65`
   - أضف أيضاً SHA-256: `EA:67:58:09:D7:76:94:40:C1:42:D4:0F:72:E6:AD:FB:D2:47:C7:65:D4:8E:38:21:1A:A0:D3:2F:B9:C3:B1:E3`
   - هاتان البصمتان للمفتاح الثابت `ci/debug.keystore` الذي يُوقَّع به التطبيق، وهما ضروريتان لعمل تسجيل الدخول بـ Google.
5. نزّل ملف `google-services.json` (للقراءة فقط، **لا ترفعه للمستودع**) وخذ منه القيم التالية:

| السر في GitHub | من أين |
|---|---|
| `FB_API_KEY` | `client[0].api_key[0].current_key` |
| `FB_APP_ID` | `client[0].client_info.mobilesdk_app_id` |
| `FB_SENDER_ID` | `project_info.project_number` |
| `FB_PROJECT_ID` | `project_info.project_id` |
| `FB_STORAGE_BUCKET` | `project_info.storage_bucket` |
| `GOOGLE_WEB_CLIENT_ID` | القيمة `client_id` للعنصر الذي فيه `"client_type": 3` داخل `oauth_client` |

6. في المستودع على GitHub افتح **Settings ← Secrets and variables ← Actions ← New repository secret**، وأضف كل قيمة باسمها.
7. من **Actions ← بناء ملف APK ← Run workflow** أعد البناء. يصبح اسم الملف الناتج `almaqal-attendance-firebase.apk`.
8. أول دخول للمدير: سجّل الدخول بحساب Google المدرج في `superAdminEmails` داخل `lib/config.dart`، وهو أيضاً في `firestore.rules`. بعد الدخول:
   - افتح **الإعدادات ← تشغيل التهيئة** لرفع الطلاب والمواد.
   - أضف الدكاترة من **الكادر**، وأسند إليهم المواد.

## البناء على جهازك (اختياري)

```bash
flutter --version          # يفضّل 3.24.x
bash ci/prepare_android.sh # يولّد مجلد android ويضبطه
flutter pub get
dart run flutter_launcher_icons
flutter build apk --release \
  --dart-define=FB_API_KEY=... --dart-define=FB_APP_ID=... \
  --dart-define=FB_SENDER_ID=... --dart-define=FB_PROJECT_ID=... \
  --dart-define=FB_STORAGE_BUCKET=... --dart-define=GOOGLE_WEB_CLIENT_ID=...
```

## ملاحظات

- **رمز QR:** يحتوي معرّف المحاضرة ورمزاً مشتقاً بخوارزمية SHA-256 من سرّ المحاضرة والوقت، ويتجدد كل 15 ثانية. يتحمّل التطبيق فرقاً في ساعات الأجهزة حتى دقيقة تقريباً.
- **إعادة تعيين كلمة مرور طالب (في Firebase):**
  - احذف مستخدمه `<الرقم>@id.almaqal.app` من Authentication ← Users.
  - ألغِ "الحساب مفعّل" من ملفه في التطبيق.
  - بعدها يستطيع التفعيل من جديد.
- **قواعد الحماية** في `firestore.rules`:
  - الطالب لا يسجّل إلا نفسه وفي محاضرة جارية.
  - السجل لا يُعدَّل بعد إنشائه.
  - التعديل اليدوي للدكتور صاحب المحاضرة والمدير فقط.
- **بنية الكود:**
  - `lib/data/` مصدر البيانات: `firebase_repo.dart` للتشغيل الحقيقي و`local_repo.dart` للوضع التجريبي.
  - `lib/screens/admin|doctor|student|common` الشاشات.
  - `lib/theme.dart` الألوان والخطوط.
